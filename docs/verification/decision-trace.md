# Capturing the actual confirmation gate

The native Ask callback cannot show whether a matched handset playout receipt preceded it. Collect the **executed** desktop decision transitions independently during the positive case. Never infer them from source, the final values, or a speech transcript.

Use an unused **loopback-only** Bun Inspector port on a private, access-controlled desktop. A debugger grants control of the paid session; if the machine or debugger is not trusted, stop. Never forward or publish the URL or open it in a hosted web debugger. Keep the same cwd, existing authenticated config, private child overlay, and model as in [the runbook](../DEBUG.md). Resolve `$cli` to stock omp 19.1.0's installed package `bin.omp` entry (`dist/cli.js`, not the development tree). Use `bun --inspect=127.0.0.1:<owned-port> $cli --config $overlay --no-session --no-extensions -e $extension -e $observer --tools ask --model $codexModel` **instead of** a second host. Do not copy credentials or create a new profile. Use a trusted local WebKit/Bun debugger; [Bun debugger options](https://bun.com/docs/runtime/debugger). Keep verbose fetch/HTTP diagnostics disabled.

Collect **non-pausing** observations; never call a decision method, change a local, read auth/SDP, inject a transcript, or manufacture a receipt. Use a debuggable approved handset build and serial-bound local Android Studio debugger for the single playout logpoint below. Use the real desktop `plugin/src/runtime/routing.ts` callbacks for the rest. Match actual executable positions in the installed builds. The host observer separately records `away-brief`, `away-consult`, `away-extract`, `away-verify` and, if used for a natural affirmative, `away-confirm`. None of these ledger entries alone proves playout or submission.

Export `decision.ndjson` for **one** original Ask and joined call, one JSON object per observed transition. Use `event`, `at` (UTC epoch milliseconds on the desktop timeline), `request` (SHA-256 of the original request ID), and the indicated identity (`mark` or `utterance`, SHA-256 of its UTF-8 bytes). Desktop example for a mark record: `JSON.stringify({event:"verified",at:Date.now(),request:new Bun.CryptoHasher("sha256").update(id).digest("hex"),mark:new Bun.CryptoHasher("sha256").update(mark).digest("hex")})`. Use the variable names actually in scope; never expand whole objects. On Android hash the two IDs with `MessageDigest.getInstance("SHA-256")` over UTF-8, convert each digest to lowercase hex. Before and after the run bracket a serial-bound device epoch-time read with desktop epoch reads; record offset/uncertainty privately. Normalize Android observation time, use the same mark and packet causality for ordering, and report inconclusive if the data do not resolve the order. Never adjust timestamps merely to make the checker pass.

| `event` | Real execution point (in order) | Identity / additional evidence |
|---|---|---|
| `readback` | Decision `createCall` → `read(draft)`: fresh mark assigned to the actual validated draft; runtime dispatches this matching marked `sendSpeakable`. Ignore ordinary brief/clarification audio. | Join `id`/`reply.mark` in runtime to the **same** `mark` in `read(draft)`. Include `draftValues` from `draft.values` only if its complete key set is `mode,note`, mode is `blue`, and the note matches the safe fixture (ASCII case variants of “retry tomorrow”, optionally one final `.` or `!`). Copy the **observed** string unchanged; for any other values export no text and mark inconclusive. Never publish unrelated form values. |
| `verified` | `onReadback` after `await decision.verifyReadback(mark,actualAssistantFinal)` has succeeded for the still-current mark; readback phase changes to `verified`. | `id`, `mark`. Independent extraction must match the structured draft, not the whole assistant script. |
| `mark` | `onMark` sends the marker on the authenticated channel **after** the verified phase and the media boundary. | `id`, `mark`. Observe actual decoded audible PCM followed by a live output boundary and drained prior audio sends; provider text completion alone is not a boundary. |
| `presented` | On Android `CallService.playback`, inside the live branch that calls `played(next)` after `AudioTrack.getTimestamp(stamp)` showed the target had been presented. | Request `id`, mark `next`. Also export `targetFrames` = `target`, `presentedFrames` = `stamp.framePosition`. No recording or transcript. A byte enqueue, write completion or estimated sleep is not this observation. |
| `played` | Desktop authenticated `onMessage` in the `played` branch, after device/request/outstanding-mark checks and **successful synchronous `voice.played(mark)`**, delivering the receipt to `decision.played`. | `message.requestId`, `message.mark` |
| `speech-start` | `onSpeechStarted` calls `decision.speechStarted` on the current call for a **new** caller utterance *after* that receipt. | `id`, `utterance` |
| `user-final` | Same joined call, matching onset and final user utterance delivered to `decision.speechFinished`. | `id`, `utterance`. Keep words private; this is the separate spoken assent, not assistant speech. |
| `accepted` | In that `speechFinished` promise continuation on entry, **before** the current-call/`say` guard, observe `reply.kind === "accepted"`. Native execution end can already have retired the call. | `id`, `utterance`; exactly one trusted native result and model continuation must independently match. |

Collect all candidate transitions for the case, not just successful ones. Keep the raw scope private; project the post-receipt onset/final (not the question/proposal) and corresponding accepted result. Multiple competing readbacks/onsets, missing proof, dropped audio, inconclusive clock correlation, or an observer pause that changes the media behavior cannot be converted into a passing single-attempt trace. Use another fresh run rather than splice records. No logpoint adds a production hook.

Readback PCM is buffered from the append and withheld from the phone until the actual assistant final passes semantic verification. `rtp.first_voiced` may precede or follow `sdk.turn.assistant`. Observe `readback.verified` → `rtp.replay.started` → `rtp.end.*` → `mark.emitted` → authenticated `mark.played` → fresh **local** caller onset. The media endpoint can be 30 quiet decoded frames or 1.2 s of inactivity after qualifying voiced audio; prior phone writes must settle. The FIFO may include overlapping post-append audio: it is not an authoritative provider turn-ID watermark. Neither an endpoint gap nor final text proves remote EOF, handset playout, or consent. Require the actual Android presentation timestamp and the operator hearing the proposed values. Limits: 2,250 × 960-byte PCM frames, 120 s readback lifetime, 15 min connected call. Internal IDs are never spoken.

For desktop live-model evidence, observe the built `session.model` on the **actual sent payload** via the return from `buildLiveSessionPayload` (model-only inspection) and the accepted `#signalWithAccess` branch paired with this join. A success code on another request is not proof. Record only the model, status and times; keep the separate paid ledger entries for the coding-model brief/clarification/extraction. If these dynamic observation points aren't available in the installed build, do not fill expected values by hand.
