# Real Away acceptance: one paid Codex session, one original Ask

**Not an E2E result.** [Native Ask gate](../plugin/DEBUG.md) and [verification ledger](verification/away-e2e.md) distinguish observed results from procedures. No fixture proves Android delivery, human speech, or a live Codex call. Use the deployed `https://away.example.invalid`, the installed `ru.eleven.ompaway`, a real desktop Codex subscription and the leased `Pixel_10_Pro_XL_99`. The account owner authorizes the spend and mic first. Stop on a missing prerequisite; never silently substitute a scripted provider, mock push, another AVD or desktop text entry. Limit to 128 failed E2E attempts total; do not automatically retry paid calls.

## Prepare a private, isolated run

1. Record UTC date, stock omp version (supported SDK: 19.1.0), component revisions, installed APK hash/version and Android build. Use the shared [AVD lease](WORKSPACE.md); never terminate someone else's emulator or reset a shared app. Match display name **Pixel 10 Pro XL (99)** to its config, then check `adb -s $serial emu avd name`; every adb invocation must name the leased serial. Boot with audio only under that lease. Use a consenting human's mic or the declared controller test-mic mode below. Select working emulator audio output, avoid desktop sound echo and keep permission/focus indicators visible.
2. Use the deployed Google-enabled app and real Play services. Compare the **installed** APK digest (collector reads `pm path`/`sha256sum`) to the approved build. Enable notifications and allow the invite channel in Android; don't force-stop the app. Check the dedicated route's normal DNS, certificate validation, and `/healthz`; no new public listeners. Confirm the relay uses the deployed Firebase Admin sender for `omp-away` and service-specific identity; app token acquisition/upload must succeed. Don't print FCM tokens, inspect keys, or send your own test push. Enrollments, registrations, capability URLs, provider/relay credentials, SDP, debugger handles and session dumps are never evidence to publish.
3. Start packets/flow accounting **before the invitation** (capture instructions below). Synchronize desktop and relay clocks, measure their offset and record uncertainty. All exported times use UTC Unix milliseconds normalized to desktop time; ambiguous ordering = inconclusive. Use a new private parent directory outside every checkout (restrict NTFS ACL to operator/system or POSIX mode 0700). Store captures separately on encrypted private scratch. PowerShell from the workspace root, with a Python 3.10+ interpreter and SDK platform-tools:

   ```powershell
   $run = Join-Path $privateParent ('away-' + [guid]::NewGuid())
   python tools/acceptance/operator_run.py init $run
   $env:AWAY_ACCEPT_DIR = $run
   $observer = (Resolve-Path tools/acceptance/observe.ts).Path
   $extension = (Resolve-Path plugin).Path
   $scenario = Get-Content -Raw (Join-Path $run 'scenario.json') | ConvertFrom-Json
   $work = (New-Item -ItemType Directory (Join-Path $privateParent ('work-AWAY-CHECK-' + $scenario.run))).FullName
   ```

   Before starting the paid host, configure [non-pausing confirmation and signaling observations](verification/decision-trace.md). The complete positive bundle requires `decision.ndjson`; human hearing plus a native result cannot establish playout-receipt ordering.

4. Use the normal authenticated desktop configuration and its existing Codex login, a separate empty working directory, and a fresh `--no-session` child. **Do not set a new `--profile`, `PI_CONFIG_DIR`, HOME or user data directory, edit global settings, or copy credentials.** Choose an available real `openai-codex` model, with no base-URL or custom live endpoint overrides, capture proxies or fixture provider. Give this child a private `--config` YAML overlay containing only the loopback Collab configuration and `ask.timeout: 0`. No public Collab link. Set `OMP_AWAY_URL=https://away.example.invalid`, `OMP_AWAY_STATE_DIR` (private absolute directory), and `OMP_AWAY_TOKEN_FILE` (absolute owner-only preprovisioned bearer file) in its launch environment. Provision desktop tunnel and media helpers per component procedures.

   ```powershell
   $overlay = Join-Path $run 'child-config.yml'
   # $port is a dedicated free loopback port; the overlay contains no credentials.
   @('collab:', "  relayUrl: ws://127.0.0.1:$port", '  autoStart: control', 'ask:', '  timeout: 0') | Set-Content -Encoding utf8 $overlay
   Set-Location $work
   omp --config $overlay --no-session --no-extensions -e $extension -e $observer --tools ask --model $codexModel
   ```

   Use the supported local Bun/omp installation; do **not** launch `plugin/test/fixtures/launch.ts` or use `confirm.ts`. Wait for local guest ready and a healthy real relay control connection. The external observer only subscribes to host lifecycle and reads the native side-turn usage journal. It never registers a provider, sends a prompt, creates an answer, or emits an event. Each evidence path is create-only; don't reuse it.

## Authenticate first; rings aren't authority

At the idle desktop composer run `/away pair`. Transfer the one-time secret only to the intended device via trusted local clipboard or trusted offline QR; never use cloud clipboard, a remote QR generator, adb shell arguments, a screen recording or a chat. Compare **all 12 emojis in order on both actual displays**. While either approval is withheld there must be no verified inbox/private question/media. Tap **Codes match** on the phone and use the exact scoped `/away approve …` shown on the desktop widget. Verify reconnect without reprompting with the same paired pins; only then open authenticated inbox. Clear the local clipboard safely. Record comparison outcome, verified reconnect and absence of private access before acceptance, not the secret, code or pins. Use `/away on`, `/away fallback off`, then `/away status` before the positive case. Background the app normally.

## Positive run: human-operated speech or declared emulator test mic

Open a second terminal. From the workspace root run `python tools/acceptance/operator_run.py live $run --serial $serial --adb $adb`. Default `--audio-source human-mic` uses consenting live speech. For reproducible **caller** audio, `--audio-source emulator-test-mic` labels operator-controlled PCM delivered to the emulator microphone through the SDK's documented, authenticated local `EmulatorController.injectAudio`; `streamAudio` captures the actual emulator speaker. Use the installed `emulator/lib/emulator_controller.proto` formats and an authorized controller bound to the same leased serial. Do not publish controller credentials. The collector performs read-only adb observations; it does not inject audio or tap the UI. Record which source was used. The test mic may replay or synthesize nonsecret caller phrases through the real Android microphone path, not pretend they were spoken by a person. The operator must listen to the actual provider output and withhold confirmation unless the fresh readback is complete and accurate. Never synthesize a provider reply, fill in a transcript, derive a challenge from debugger variables, or insert a playout receipt.

After the notification baseline the collector prints a two-word name for Blue's disposable test environment and a separate per-run canary. The canary is in the basename of `$work`, which the verified inbox displays as the project name. Send the following once from that workspace, substituting only the environment name. Keep `scenario.json` and the separately generated voice-only note out of the coding session.

> We need to choose a release lane. Green affects production. Blue is the only lane with a disposable test environment; its two-word, nonsecret name is [environment name]. Omit the name from the initial form and spoken brief. If the caller asks which disposable environment Blue uses, give its exact name so they can distinguish it from production. Call the built-in Ask tool once with a single HTML form: a fieldset with legend “Choose lane”, two radio buttons named `mode`, Green lane (`green`, selected by default) and Blue lane (`blue`); a labeled required textarea named `note` with label “Test note”. No hidden fields or prefilled note. Wait for its result; then report the returned mode value and exact note in one sentence. No other tools or calls.

Follow `operator_run.py` prompts in order. The native form remains open throughout, untouched by the desktop operator. Compare identities and UI, not timing alone:

- Observe the actual notification shade: **Desktop request / Open your inbox to review.**, not the question, note, credentials or content. The collector fingerprints the active OS notification tag from `cmd notification list`; it must equal the desktop offer's fingerprint. A 204/message ID is NOT delivery, and a notification manager record alone is NOT a witness to visible pixels. Tap **Not now** on the notification, observe it disappear; the same Ask must remain on desktop and in the freshly authenticated phone inbox. If its draft is not available offline, a cached entry is not proof.
- Open the correct inbox item, consent to microphone, then **Answer by voice**. Hear the actual question through emulator output. Ask **“What is the name of the disposable test environment for Blue lane?”** Do not say its name yourself. Report only the name heard in the real reply. Native Ask must still be open, and the host ledger must show a separate successful `away-consult`, not a replay of the brief or an ordinary agent/user turn. The name is a nonsecret fact about the pending choice; do not ask for unrelated history or weaken consultation privacy rules. A source text file, injected transcript, synthetic provider/readback audio or fabricated `played` is not evidence.
- When prompted, say “My answer is Blue lane; my test note is …” with the **voice-only** note. Listen through the **entire** canonical readback, check label/value, note and fresh challenge. Do not confirm an inaccurate or interrupted readback; stop this attempt. The form must still be pending immediately before confirmation. Only then speak the exact affirmative and fresh words, with no text injection. See the original dialog disappear **once**, native composer return, refreshed phone inbox clear, and the actual model report `blue` and the note. A log of a button press, assistant readback, a local fixture mailbox result or desktop rendering alone is insufficient. Exit this isolated host cleanly with `/exit` after the model's final turn so the observer closes its log.

## Collect the two independent network views

**Phone egress.** Use an approved on-device UID-attributed capture (e.g. PCAPdroid local VPN connection inventory, non-decrypting) on this AVD, with both the app UID and `com.google.android.gms` included. Record mapping from `adb -s $serial shell cmd package list packages -U` without publishing the whole list. Start before the fresh notification baseline; end after the verified inbox is cleared. Include active/persistent sockets, every enabled IPv4/IPv6 interface, TCP and UDP/QUIC, retries and unresolved connections. Do not also use a system VPN or certificate interception. Confirm capture routing, exemptions, drops and that the run contains actual bidirectional relay and Google connections; if Play services bypasses the collector, the VPN restarts, a resolver can't be attributed or a preexisting socket can't be seen, do not mark full coverage. Cross-check with emulator-interface capture or independently attributed per-UID flow data if needed. Map addresses using contemporaneous DNS answers + SNI/connection metadata, not reverse DNS or ownership of a shared CDN IP. Include unknown flows, don't filter them out. Record system resolver activity separately and identify the observed names; an opaque DoH/proxy path cannot prove final destinations. No OAI/ChatGPT host, public Collab, SIP, Tailscale or other destination is allowed. Other background system UIDs are not evidence of app egress.

**Relay.** Use only the authorized dedicated acceptance route/process and window. Capture *after* the public outer TLS terminator (nginx → dedicated relay loopback backend), starting before the invite/phone upgrade, through native completion and an orderly close. A capture on public :443 simply sees nginx's TLS and proves nothing about relay access. An authorized operator can use `dumpcap -i lo -f "tcp port 8787" -s 0 -w <private-scratch>` **only if** that backend and every connection in the interval belong to this test; confirm actual backend port. Otherwise isolate an owned route/window, or stop. A pcap at this point can contain outer bearer headers, FCM token registration or one-time enrollment data: never share/print it. No `-A`, verbose HTTP logs, TLS key logging, forwarding token-bearing URLs, or whole-host traffic capture. Inspect under local access control. Check zero drops, no gaps or truncation; record clock relation.

1. In Wireshark identify the first `POST /v1/invites` for this fresh request and its `204`, with the deployed real Firebase sender. Confirm precisely one new send, not duplicate/coalesced/cached success. Check the Firebase project send counter/audit if available (isolated interval). A non-204, unregistered token, fake sender or ambiguous duplicate is not a pass. Use Follow TCP Stream, choose each direction separately, **Show data as Raw → Save As** locally. Use exactly the request and its response; if a keep-alive stream has other transactions, isolate these PDU bytes securely rather than ingest the whole connection. On the authorized capture machine run `python tools/acceptance/invite_projection.py <run-dir> <request.raw> <response.raw>`. Only `scenario.json` is needed as input in the private run dir. 2. Identify the single `/v1/phone` HTTP/1.1 WebSocket on which the verified inbox and positive voice call occurred, **not** `/v1/control` or a background silence-only tunnel. Match sole paired device, join/finish times, direction and changing byte counts; no concurrent calls. Select from GET/101 through close with TCP reassembly and no missing segments. Follow TCP Stream → Raw, save nginx→relay and relay→nginx **separately**. Run `python tools/acceptance/relay_projection.py <run-dir> <nginx-to-relay.raw> <relay-to-nginx.raw>`. It removes actual WS masks, checks TLS 1.3 offer/selection and both directions, and searches reassembled payload for the per-run canary seen in the verified inbox project name. 3. On the **desktop only** independently observe real Codex signaling for this call: trusted debugger/SDK observation at the successful `LiveTransport.#signalWithAccess` return or equivalent, showing the model selected in the sent session payload, real Codex route, positive response with SDP and established sideband/media. Use only a local secured observer (never expose a debug port), inspect *only* selected model and status; do not expand headers, access, SDP, sideband URL or call ID. A source constant, account login or encrypted IP flow alone is not an observed live session. Record model, UTC interval, observation method and successful two-way audio. ## Additional real scenarios (separate requests/runs)

Use a different fresh **nonsecret** request marker per case. Record expected vs observed state, actual timestamps, distinct original Ask/notification fingerprints, native result counts and thread ownership. Do **not** append these extra turns to the positive run. For expected absence, hold a full explicit observation window (e.g. twice the configured escalation delay, at least 60 s); give the actual start/end. No UI control or stale payload injection.

| Case / operator action | Required observation |
|---|---|
| Normal routing: `/away off`, `/away fallback off`; wait, then `/away fallback 15` on a fresh request | No disabled invite; normal desktop form remains open. On the delayed case no OS record before deadline, one request-specific visible invite after it. Early desktop completion cancels the timer. `/away on` rings without that delay. |
| Swipe OS notification away without opening it; then separately use **Not now** | Shade record gone; no mic or submission. Open paired app normally, refresh; same desktop Ask available. **Not now** silences future ringing for that ID across reconnect. Swiping need not equal protocol `silence`. |
| Miss a push: keep handset disconnected longer than observed FCM TTL (configured 45 s); reconnect | No late ring for expired push; fresh authenticated list still has untouched Ask. A cancelled/completed Ask disappears on reconciliation. An old notification or cached entry must never start media against a different Ask. |
| Open invite without joining, hang up during real call, interrupt readback, say only “yes”, reject a draft or alter it | No mic on mere invite/open. Hangup stops mic/playback and releases media; Ask remains pending. Interrupted/mismatched readback and ambiguous speech never submit. Changed draft requires a new full readback/affirmative; old challenge does not resolve it. No default from silence. |
| Desktop wins while phone pending; then leave successor Ask open | Submit distinguishable desktop values. Old call ends; stale cached entry/reconnect/attempted late affirmative cannot submit a second result or mutate successor. The fresh inbox binds the new request only. |
| Stale/timeout | Keep native `ask.timeout=0` in all supported runs. Join from a stale notification after desktop cancel/finish; bound the wait (e.g. 90 s), observe no mic/accepted result for old or successor. Separately withhold network during side-turn/setup and wait more than its configured deadline (60 s plus margin); require error/ended media, original Ask still pending, no default/native result or late delivery after reconnect. A 45 s push TTL, setup timeout, enrollment expiry and native Ask lifetime are different. |
| Changed key, bad comparison or expired enrollment | Only on disposable, independently authorized profile/identity. Decline one comparison: no private list/call. Let a fresh ticket expire (>10 min) or reuse a consumed ticket: rejected. With existing pins, rotate the **test** counterpart via legitimate new identity, never export a key; require mismatch/no private data until fresh explicit mutual pairing. Do not rotate the production operator's identity just to run this case. |

**Limits and cleanup.** Encrypted application-data records may include handshake/alerts; counts are not PCM proof. The relay sees timing, sizes, addresses, route/auth metadata, FCM registration and opaque request IDs. One absent plaintext canary and readable TLS records are not proof that no other content is leaked, nor that a compromised endpoint is safe. Packet capture can't prove speech was intelligible or a person heard it. Conversely, a human hearing words can't establish network path or exact native result. Report handset-UID and capture limitations explicitly; this is not a lifetime guarantee about all apps on Android. Preserve only reviewed sanitized evidence per [ledger](verification/away-e2e.md). Close paid session, turn off only owned captures/debugger/mappings, release microphone and owned lease, clear one-time clipboard, and dispose of credential-bearing scratch under local policy. Don't wipe devices or modify other profiles/services.
