# Away/1 wire contract

Deployment serves one operator/desktop route. Outer HTTPS API uses a 256-bit desktop bearer provisioned on both relay and desktop; `Authorization: Bearer ...` always, no tokens in URLs. The phone bearer is separate. The public relay is not an authority for inner TLS. Reject redirects for authenticated requests. JSON request and response names below are case sensitive; success without body is 204.

| Operation | Input → output |
|---|---|
| `POST /v1/enrollments` desktop | `{}` → `{ticket}` fresh random base64url token, one-time, ten-minute expiry |
| `POST /v1/enroll` unauthenticated | `{ticket}` → `{deviceId,token}` new random route + phone bearer; expired or used ticket rejected |
| `PUT /v1/token` phone | `{fcmToken}` → 204; replace for this device only |
| `POST /v1/invites` desktop | `{deviceId,requestId}` → 204; real FCM HTTP v1 high-priority data-only message with just `requestId`, short TTL, duplicate invite coalesced. Android immediately renders a user-visible generic notification with a Not now action. No raw question |
| `GET /v1/control` desktop WebSocket | Relay text frame `{"type":"connect","deviceId":"…","connectionId":"…"}` per waiting phone; reject a second desktop connection |
| `GET /v1/phone` phone WebSocket | Phone initiates tunnel; after control message, relay matches desktop opening `/v1/tunnels/{connectionId}` with desktop bearer. Raw binary TLS bytes in both directions; queue bounded or backpressure until desktop connects; no other frame protocol on these sockets |
| `GET /healthz` | 200 no secrets |

Pair QR/clipboard payload: JSON `{v:1,url:"https://away.example.invalid",ticket,desktopPin,nonce,secret}`. `desktopPin` is unpadded base64url SHA256(DER SPKI). `nonce` and `secret` are independent 32-byte random values encoded unpadded base64url. Inner TLS 1.3: phone verifies desktop pin even on first contact; desktop verifies the phone proved possession of its presented client key. First enrollment can use a self-signed client certificate but **requires** successful TLS CertificateVerify, fresh secret and both emoji confirmations before any private data. After enrollment both directions require pinned keys. A changed key never automatically replaces a pin. Emoji digest = SHA256(ASCII `omp-away/1` + 0x00 + raw desktopPin digest + raw phonePin digest + raw nonce); encode first 6 bytes as twelve hex nibbles mapped to the ordered Unicode list `🐶 🐱 🦊 🐻 🐼 🐸 🐵 🐯 🦁 🐷 🐨 🐰 🐙 🐧 🐳 🐢`. Compare 48 bits, not a single emoji. Public route tokens never authorize private requests.

Inside TLS frame: 1 byte kind (1=UTF-8 JSON, 2=signed-16 little-endian 24 kHz mono PCM, exactly 960 bytes), 4-byte unsigned big-endian length, payload. JSON cap 64 KiB. Reject unknown kinds, oversize frames or unexpected direction. Pairing only: phone `{type:"pair",secret,nonce}`, desktop `{type:"verify",emoji}` as a check only (Android computes locally and compares), phone `{type:"verify",accept:true}`, desktop `{type:"paired"}` only after local operator approval. For a verified socket phone sends `{type:"list"}`, `{type:"join"|"silence"|"hangup",requestId}` or `{type:"played",requestId,mark}` (only after prior audio physically drains). Desktop sends `{type:"inbox",items:[{requestId,project,question,createdAt}]}` (`createdAt` epoch milliseconds), `{type:"joined"|"ended",requestId}`, `{type:"mark",requestId,mark}`, `{type:"error",code}`. One joined call per tunnel. Never receive submitted form values or untrusted tool calls from the phone. Desktop holds and validates them from decision conversation. Disconnect releases media, not the Ask. Offline inbox reconciles on reconnect.

Desktop helper boundary: Python runs the handset tunnel TLS and desktop aiortc in separate helpers; Bun orchestrates streaming, signaling, and requests. Subprocesses exchange length-bounded data and control; no protocol-over-stdout logs. Child processes never get Codex secrets. Helpers may communicate arbitrary binary only over framed stdio. Keep subordinate credential handling off the public relay. Publish neither capability links nor raw session transcripts.
