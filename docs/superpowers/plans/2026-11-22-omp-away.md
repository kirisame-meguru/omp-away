# omp-away Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Answer the original desktop Ask via an authenticated Android voice conversation without exposing the coding session to the phone.

**Architecture:** Use a desktop-only Collab writer to resolve host-generated field prompts. Bridge the handset to desktop over mutually pinned TLS inside an opaque relay tunnel; originate Codex WebRTC on desktop. Only the desktop stores private question/decision records; the relay queues wakeups and carries bytes.

**Tech Stack:** Bun/TypeScript omp extension, Python aiortc desktop media helper, Go HTTPS/WebSocket relay with Firebase Admin SDK, Kotlin Android app with Firebase Messaging, Android Keystore and native PCM audio. Use existing TLS and WebRTC implementations, not a custom cipher or a fork of omp.

**Spec:** `docs/superpowers/specs/2026-11-22-omp-away-design.md`

## Global Constraints

- Root is `~/Claude/omp-away`; `android/`, `relay/`, `plugin/` are independent repositories. Root coordinates, ignores those working trees, and owns cross-component docs. Never create a README.
- No writes to `oh-my-pi` or `jtarchive`. Only native built-in Ask. No arbitrary chat forwarding, simulated keypresses, monkey-patching or public Collab fallback.
- Real `Pixel 10 Pro XL (99)`, FCM and Codex required for acceptance. Do not silently replace a missing test device. Do not start a shared AVD without the per-AVD lease; don't use the reference project's `-no-audio` flag.
- No Codex credentials on the relay or handset, no FCM service credentials on handset or desktop extension. No answers or plaintext audio in relay logs. No production secrets committed in any repo.
- Never advance a request on delivery, timeout, clarification, disconnect, or notification dismissal. Stop at 128 failed E2E attempts, not 128 automatic calls.

### Task 1: Prove a confirmed guest answer resolves the real local Ask

**Files:** `plugin/src/collab/{adapter,responder}.ts`, `plugin/src/index.ts`, `plugin/test/collab.test.ts`, `plugin/prompts/fixture-ask.md`, root `.gitignore`, `docs/WORKSPACE.md`. The root ignore list includes `/android/`, `/relay/`, `/plugin/`. Initialize each Git repository in its owner directory, never as a submodule. Install the extension in an isolated test profile; do not change the current user's global Collab settings.

**Interface:** `submitConfirmed(requestId: string, values: FormValues): Promise<'accepted'|'stale'>`, `type FormValues = Record<string,string|number|boolean|string[]>`. Keep a local mapping from session generation + Ask tool-call ID to the original HTML form and current guest UI request ID. Guest frames are not a bulk form API: drive select/editor steps in order. Do not expose arbitrary Collab frame input to the phone.

- [ ] Write a two-field Ask scenario (one labeled radio, one required text field). Test private guest selection and final text map to HTML **values**, not display labels. Also test that a second submission after a local win cannot answer the next Ask.
- [ ] Run `bun test test/collab.test.ts` in `plugin/` before implementing. Bind the relay adapter explicitly to `127.0.0.1`, not Bun's all-interface default. Implement only room handshake, identity proof, guest UI requests, response and request-end. Ignore welcome snapshot contents; never persist or forward session mirrors. Keep writer capability in desktop memory. Verify relay origin and session id/generation before acquiring a link. Refuse an incompatible existing room without exposing its control link.
- [ ] Set the test profile's `collab.relayUrl` to the adapter and `collab.autoStart=control`, `ask.timeout=0`. Give a readiness error if those prerequisites are not met. Correlate only `ask` tool calls, never another `select`, approval or editor prompt. If correlation is ambiguous, fail closed rather than answer. Test cancellation midway through multi-field submission.
- [ ] Use a real interactive omp instance, not only a fake protocol server: open the fixture Ask, leave it on screen, submit via the plugin, verify original tool result, no duplicate turn, no open dialog. Repeat with a desktop win. Capture sanitized evidence in `plugin/DEBUG.md`; commit in `plugin/` after checks pass. This is the first implementation gate.

### Task 2: Desktop request state and side turns

**Files:** `plugin/src/{requests,routing,consultation}.ts`, `plugin/prompts/{brief,consult,readback}.md`, `plugin/test/requests.test.ts`. **Interface:** desktop issues a cryptographically random `requestId` scoped to host session generation and tool call. Commands `list`, `join`, `silence`, `hangup`, `answer` operate only on a paired device's request. `silence` affects notifications; `hangup` ends media; neither changes the underlying Ask.

- [ ] Write clock-driven tests for escalation disabled, escalation delayed, immediate `/away`, cancellation before the deadline, silence surviving reconnection, and stale/duplicate results. Example assertion: `silence(id); clock.advance(delay * 2); expect(pushes).toEqual([id]); expect(listPending()).toContain(id)`.
- [ ] Run `bun test test/requests.test.ts` red. Implement one pending record per actual Ask and one cancellable timer. Persist nonsecret user preferences for `/away` and fallback delay. Invalidate stale IDs when the owning tool ends. Desktop state is authoritative; rejoining clients fetch a fresh list via the authenticated tunnel.
- [ ] On a pending request create a bounded brief via `ctx.runEphemeralTurn({promptText, tools:false, signal})`; if the side turn cannot run, retain the desktop form and show a call error instead of fabricating rationale. Bind clarification history to that request. No use of `sendUserMessage`, normal `/live` delegations or tool execution.
- [ ] Exercise ordinary proposals without fixed phrasing. Verify the meaning of the actual assistant readback against the complete structured draft independently of filler or paraphrase. After a matching authenticated handset playout receipt, accept a separate fresh natural affirmative once. Test early/duplicate yes, missing/changed values, interruption, new draft and stale receipts. The caller must never repeat codes or confirm an exact assistant script. Malformed values stay local; native finish/abort cleans up. Run `bun test`, commit.

### Task 3: Public relay and private pairing

**Files:** `relay/cmd/away-relay/main.go`, `relay/internal/{routes,tunnel,registration,push}/`, `relay/internal/routes/integration_test.go`, `plugin/src/{pairing,tunnel}.ts`, `plugin/test/pairing.test.ts`, `android/app/src/main/java/ru/eleven/ompaway/security/PairedChannel.kt`. **Interfaces:** outer endpoints for provisioned desktop registration, single-use phone enrollment, authenticated FCM token rotation, and tunnel creation. Versioned tunnel messages expose only random device/request/connection IDs, fixed message kinds and ciphertext lengths. Outer bearer possession is not proof of inner TLS peer identity.

- [ ] Write relay tests using a recording fake FCM sender and two real WebSockets. Reject wrong device/token, expired/reused enrollment, wrong counterpart and oversize frames. Assert wake payload contains only generic notification text and opaque ID; no app-supplied free text. Test disconnect frees tunnel buffers. `go test ./...` must fail for unimplemented paths.
- [ ] Implement bounded in-memory tunnel piping, durable token/route associations, monotonic expiry for outstanding invites, deadlines, and idempotent delivery. Verify Firebase invalid-token responses remove only the token used on that attempt. Use application-default credentials or a service-specific credential file outside Git. Tests must not send real pushes.
- [ ] Generate desktop certificate/key locally with user-only access. Use an app-generated nonexportable Android Keystore signing key and certificate. Provision phone with desktop SPKI hash + random one-use enrollment secret from desktop QR; the initial inner TLS session must pin that hash before transmitting anything sensitive. Present phone certificate and prove key possession in the TLS handshake. Show the same emoji fingerprint derived from versioned, role-ordered certificate hashes and enrollment nonce at both ends. Require explicit confirmation at both endpoints; after enrollment require exact pins and TLS client authentication. Reject old pairing after rotation; never fall back to unauthenticated TLS.
- [ ] Integration test tunnel with unique plaintext sentinel and two different key pairs. Assert pinned endpoints recover sentinel and relay wire capture does not contain it. An active relay swapping either certificate must fail, as must a new phone presenting the prior device's routing token. Never disable normal public TLS validation. Run `go test ./...` and `bun test test/pairing.test.ts`, then commit in owning repos.

### Task 4: Desktop voice bridge without execution authority

**Files:** `plugin/src/{voice,media-helper}.ts`, `plugin/media/{peer.py,pyproject.toml}`, `plugin/prompts/voice.md`, `plugin/test/voice.test.ts`, `plugin/media/tests/test_peer.py`. **Interface:** caller creates an SDP offer with one bidirectional Opus audio track and `oai-events`. Desktop adapter owns the sideband. Inner phone channel carries signed-16 little-endian mono PCM, 24 kHz in 20 ms frames (960 bytes per frame), request-scoped control and explicit playout completion. Use bounded queues and drop stale audio instead of replaying speech after reconnect.

- [ ] Test voice boundary using a fake transport that emits `delegation.created`. The only callable handler may consult the current coding model with `tools:false`; reject work requests, return speakable context with the same delegation ID, never call session steering/command APIs. Exercise clarification, negative response, barge-in and hung-up call while consultation is outstanding. `bun test test/voice.test.ts` red.
- [ ] Instantiate the matching omp SDK `LiveTransport` directly using `ctx.modelRegistry.authStorage`, current session ID and desktop media helper SDP (not `ctx.startLive()`, whose controller turns delegations into agent turns). Verify the SDK subpath and native dependencies work under the installed packaged omp before expanding implementation. Fail clearly on unsupported versions. Feed the speech model the brief, not session history. Use protocol helpers for context messages; never pass raw data-channel messages from Android.
- [ ] Implement the desktop aiortc peer with framed stdio, monotonic audio timestamps and resampling for negotiated Opus. Add a bidirectional tone test with two real local peers to catch inverted tracks, a muted return path or unbounded playback queues. Run the helper with a private subprocess environment and no listening TCP endpoint. `uv run --project media pytest media/tests`; `bun test`. Commit.
