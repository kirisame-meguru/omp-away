# Desktop decision integration

Import `DecisionCoordinator`, `loadPreferences` and `savePreferences` from `./decisions`. The coordinator belongs to one host session generation and does not authenticate devices. Only preferences belong on disk. Never serialize a `PendingAsk`, a `DecisionCall`, or a submission capability.

Use one coordinator per paired identity, or share one **only** behind request-scoped authorization. Snapshot eligible pinned identities at Ask birth and intersect that audience with currently authorized pins for every inbox, invitation and join. Require the same live pinned tunnel and joined request for media. Revocation closes the active call; a new enrollment never inherits old requests. Never forward an unfiltered shared inbox.

- `offer(pending, ctx, project)` receives the original live native capability after its guest controller is bound. `false` means no mobile offer. Call `end(requestId)` synchronously on every native finish, desktop answer, approval, room loss or abort that retires the capability, before resolving its result. `close()` seals the generation; do not reuse it after switching sessions.
- `configure({away,delayMs})` rings immediately in away mode; otherwise `null` disables escalation and a nonnegative delay is measured from creation. Each request rings once. Invalid persisted preferences must not enable ringing. A missed invitation or failed voice call does not expire the Ask.
- `list()` returns inbox items; `silence(id)` affects notification only. `join(id)` requires an eligible request and no other active call. Bind that call to the authenticated tunnel/request and subscribe to `call.signal` before opening media. Hangup or disconnect calls `call.close()`, not `end()`. Reconnect obtains a fresh call with no old proposal.
- `await call.brief()` supplies bounded native question text immediately, without a model summary. Narrate `call.opening()` after join. Contextual questions use `call.consult(question)`, a bounded tool-free side turn in the owning coding session; direct menu questions use the native labels. Consultation invalidates confirmation and cannot submit.
- Provider audio streams as it arrives, paced on its 20 ms sample clock with a 100 ms handset lead. There is no assistant-final, semantic-verification or handset-acknowledgment gate. Unchecked speech may be heard; it cannot alter the canonical proposal or authorize a submission. Transport backpressure remains bounded.
- Send `call.speechStarted(id)` for caller onset and `call.speechFinished(id,text)` only for its uniquely associated final user transcript. Assistant speech, partial transcripts and provider delegations cannot authorize a decision. Overlapping, duplicate or unbound turns cannot approve a proposal.
- A unique enabled option label in a single-select field drafts locally through the native validator. Other proposals and partial corrections use tool-free extraction. Native validation still rejects invalid values, disabled options, missing field evidence and inferred defaults. Hidden values remain local.
- A proposed reply carries `{kind:"say",text,draft}`. `draft` is an immutable list of visible labels and display answers; `text` instructs the voice model to briefly read them and ask whether to submit. Pass it to `sendSpeakable(text,true)`. Its field values are serialized as untrusted JSON, never executable instructions. Ordinary narration uses `sendSpeakable(text)`.
- Only a separate explicit affirmative such as “yes”, “yes, submit”, or “go ahead” submits the unchanged proposal. This is local interpretation, not another model verification call. Capture the proposal at caller onset: a yes that began before the proposal existed cannot be saved for later. No finished assistant transcript or physical-playback acknowledgment is required.
- Cancellation, corrections and consultation invalidate the previous confirmation. Corrections require a new explicit affirmative. A repeat reads the current proposal again; it does not create a new Ask. A fresh call or request never inherits a draft. Legacy `played` messages are ignored and have no authority.
- `ignored` does nothing; `stale` is not success. `accepted` requires the original native capability's matching result. Submission is attempted once; failure or ambiguity cannot be retried through that capability. Finish such a form on the desktop.
- The only model operations are contextual consultation and nontrivial proposal extraction. Extraction requests the SDK's `minimizeEffort` control on the existing host model; consultation retains session reasoning. The context byte cap rejects oversized history rather than truncating it. Category-only timing contains no prompts, transcripts or answers.
