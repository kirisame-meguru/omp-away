# Desktop decision integration

Import `DecisionCoordinator`, `loadPreferences` and `savePreferences` from `./decisions`. The coordinator belongs to one host session generation and does not authenticate devices. Only preferences belong on disk. Never serialize a `PendingAsk`, a `DecisionCall`, or a submission capability.

Use one coordinator per paired identity, or share one **only** behind request-scoped authorization. For a shared coordinator, snapshot eligible pinned identities at Ask birth. Intersect that fixed set with currently authorized pins for each list item, invite, join, and silence. Require the same live pinned tunnel and joined request on every media event and playout acknowledgment. Revocation closes its active call immediately; a new enrollment never inherits an old audience. A shared coordinator rings and silences once per request and allows only one active call. Never forward its unfiltered `list()` to a shared audience.

- `offer(pending, ctx, project)` receives the original, live `PendingAsk` only after the native guest controller has bound it. Its existing random ID is used unchanged. The side turn gets the owning session context. `false` means no mobile offer. `end(requestId)` must run synchronously on **every** native finish, desktop answer, approval, room loss or abort that retires this capability. Invoke it before resolving the native result. `close()` seals the generation on teardown; never re-use it after switching sessions. Replacing a pin also retires its old coordinator or revokes all access for the old identity under a shared coordinator.
- `configure({away,delayMs})`: away rings now; otherwise `null` disables escalation and a nonnegative integer counts milliseconds from the item's creation. Each request rings at most once. Use `loadPreferences(profilePath)` and serialized `savePreferences(profilePath,prefs)`; handle invalid/unreadable settings as an error, not an enabled fallback. Pass `invite(id)` to send only the opaque request ID; `changed()` means reconcile the authenticated inbox; `error(code)` receives no model or transport text. A missed invite, timeout during a side turn, or failed delivery does not expire the Ask.
- On a pinned connection, `list()` returns wire inbox items. `silence(id)` affects that request's notification only. `join(id)` returns a call only when the request is still eligible and no other joined call owns media. Tie this object to that exact tunnel/request. Subscribe to `call.signal` **before** starting media; an already-aborted signal means stop immediately. On hangup, supersession, transport error, or disconnect call `call.close()`; do not call `end()` merely because a phone disappeared. On reconnect fetch a fresh list and obtain a fresh call.
- `await call.brief()` uses the native question directly for a self-contained single-choice field; other forms use the coding session's bounded background context. Failure keeps the native form pending. After join, narrate `call.opening()` without waiting for speech. For a single field this is its native question rather than the background explanation. `call.consult(question)` lists native options for a direct menu question, or uses a bounded, tool-free side turn for context. Use replies only on the still-current call. Consultation invalidates any armed readback and cannot submit.
- Send `call.speechStarted(id)` at an observed user onset and `await call.speechFinished(id,text)` for its uniquely associated final user transcript. Never pass assistant speech or phone JSON as a user turn. A natural complete choice needs no special introductory phrase. Missing or overlapping onsets, interrupted output, new assistant turns and lost synchronization invalidate the readback with `call.interrupt()`. A repeat creates a new marker, never a new Ask. No missing field is supplied from a default.
- An entire, unique enabled option label in a single-select field is resolved through the native validator without model extraction. Questions, negations, disabled or ambiguous labels and more complex forms still require interpretation. This creates only a proposal; independent readback, authenticated playout and fresh assent remain mandatory.
- `call.verifySpeech(expected,actual)` approves identical narration after trimming outer whitespace without inference; paraphrases still require a faithful-speech assessment. This method cannot arm a decision readback. Mechanical extraction, speech checks, independent readback and assent classification request the stock SDK's `minimizeEffort` control; background context and substantive consultations retain session reasoning. No model is substituted, and the context byte cap is a rejection bound, not history truncation.
- A marked reply carries `{kind:"say",text,mark,draft}`. `draft: SpokenDraft` is an immutable list of visible field labels and proposed display answers. Pass `text` to the voice model as the desktop's instruction, not a script to quote: the draft has not been submitted, read every answer aloud naturally now, and ask whether to submit. The message ends with the visible fields serialized as untrusted JSON data. The mark is only for desktop/handset signaling; never say it. The voice model never receives a submission capability or hidden values.
- On the completed assistant turn, pass its actual final transcript to `await call.verifyReadback(mark,transcript)`. A bounded tool-free assessment independently extracts the answers from that transcript without receiving the expected draft. All visible fields need evidence; the reconstructed canonical values must match the pinned proposal. Missing, conflicting, ambiguous or unsupported readbacks fail closed; no phrase list governs commentary. A true result is not evidence of physical playback and does not submit.
- After a successful assessment, media must establish completed readback audio and send the mark after its ordered PCM writes. Route `played(requestId,mark)` only from the same authenticated joined handset after physical drain. `await call.played(mark)` can only arm; never synthesize it or infer it from a transcript or timeout.
- Only a new user utterance whose observed onset follows that acknowledgment can approve the unchanged proposal. “Yes” or “yes, submit” is enough; longer natural assent is assessed in a scoped tool-free turn. Conditional or negative replies, corrections, ordinary discussion, stale IDs and missing speech starts are not authorization. On a correction acquire a fresh readback and playout acknowledgment. The authoritative native values are private and fixed from proposal through submission.
- An early “yes” cannot be saved for later. If a validated proposal still exists, the desktop explains that it has not submitted and repeats that proposal with a fresh mark. A new verified readback, acknowledgment and separate affirmative are all required. With no current proposal it does nothing.
- A partial revision can carry forward unchanged answers only from the same call's previous validated proposal. A new call or a new Ask starts without a draft. For ordinary multiword prose the verifier tolerates ASR sentence-initial capitalization and final sentence punctuation; it never rewrites the submitted note. Choice identities, numerics and other text remain exact. If two offered choices have indistinguishable spoken labels, use the native desktop form instead.
- `ignored` does nothing. `stale` is not success. `accepted` reflects only the original native capability's matching result. The synchronous native end may have already closed this call while the result was in flight. A failed or ambiguous submission cannot be retried through this capability; finish the form on the desktop.
