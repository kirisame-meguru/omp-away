# Desktop decision integration

Import `DecisionCoordinator`, `loadPreferences` and `savePreferences` from `./decisions`. The coordinator belongs to one host session generation and does not authenticate devices. Only preferences belong on disk. Never serialize a `PendingAsk`, a `DecisionCall`, or a submission capability.

Use one coordinator per paired identity, or share one **only** behind request-scoped authorization. For a shared coordinator, snapshot eligible pinned identities at Ask birth. Intersect that fixed set with currently authorized pins for each list item, invite, join, and silence. Require the same live pinned tunnel and joined request on every media event and playout acknowledgment. Revocation closes its active call immediately; a new enrollment never inherits an old audience. A shared coordinator rings and silences once per request and allows only one active call. Never forward its unfiltered `list()` to a shared audience.

- `offer(pending, ctx, project)` receives the original, live `PendingAsk` only after the native guest controller has bound it. Its existing random ID is used unchanged. The side turn gets the owning session context. `false` means no mobile offer. `end(requestId)` must run synchronously on **every** native finish, desktop answer, approval, room loss or abort that retires this capability. Invoke it before resolving the native result. `close()` seals the generation on teardown; never re-use it after switching sessions. Replacing a pin also retires its old coordinator or revokes all access for the old identity under a shared coordinator.
- `configure({away,delayMs})`: away rings now; otherwise `null` disables escalation and a nonnegative integer counts milliseconds from the item's creation. Each request rings at most once. Use `loadPreferences(profilePath)` and serialized `savePreferences(profilePath,prefs)`; handle invalid/unreadable settings as an error, not an enabled fallback. Pass `invite(id)` to send only the opaque request ID; `changed()` means reconcile the authenticated inbox; `error(code)` receives no model or transport text. A missed invite, timeout during a side turn, or failed delivery does not expire the Ask.
- On a pinned connection, `list()` returns wire inbox items. `silence(id)` affects that request's notification only. `join(id)` returns a call only when the request is still eligible and no other joined call owns media. Tie this object to that exact tunnel/request. Subscribe to `call.signal` **before** starting media; an already-aborted signal means stop immediately. On hangup, supersession, transport error, or disconnect call `call.close()`; do not call `end()` merely because a phone disappeared. On reconnect fetch a fresh list and obtain a fresh call.
- `await call.brief()` must succeed before starting speech. It returns a bounded session-generated brief and spoken proposal instructions. An unavailable/malformed side turn rejects; report the generic call error and hang up, keeping the native form. `call.consult(question)` answers only with a bounded, tool-free side turn; reject execution delegations at ingress. Use results only on the still-current call. Consultation invalidates any armed readback. Neither discussion nor a proposed draft submits.
- Send provider VAD `call.speechStarted(id)` and the exact associated final **user** transcript `await call.speechFinished(id,text)` (never assistant output, synthetic speech, or phone JSON). IDs must be unique per utterance, with a single ordered VAD start. Missing/overlapping identifiers, barge-in, interrupted output, new assistant turns or transport desynchronization: `call.interrupt()`; never guess the utterance. Plain discussion is ignored. A complete explicit proposal starts with “My answer is” or “I choose”; “Repeat the readback” obtains a new challenge for the current draft. Named options must be spoken by label or value. Omitted editable fields are never filled from native defaults. Immutable hidden values are restored locally, never sent to the voice model.
- An unmarked `say` reply is ordinary speech. A marked reply carries `{text,mark,confirmationPhrase}`; use `sendSpeakable(text,mark,confirmationPhrase)` on the bound desktop voice bridge. Read `text` **verbatim**. The affirmative includes four unpredictable words at the very end of the readback; the entire affirmative itself is never spoken by the assistant. A repeat or changed draft gets a new random mark and phrase. No caller-defined draft/confirmation method exists.
- For the pinned live SDK, media verifies that the assistant completed the **exact** canonical readback and that a new, nonoverlapping user utterance then supplied the entire affirmative and acoustic tail. Only that path may invoke `call.provisionalConfirmation(mark,utteranceId,finalTranscript)` in lieu of ordinary VAD/transcript callbacks for that utterance. `true` is provisional, **not submitted**. Send the marker after the matching readback's PCM. Never issue a marker based on provider transcript completion alone. A barge-in, correction, stale call or mismatching acoustic receipt invalidates the pending mark. No watermark/proof? No submission.
- Only route an authenticated, outstanding `{type:"played",requestId,mark}` from the same joined socket to `await call.played(mark)` after handset audio has physically drained. A staged affirmative and a matching played marker together cause at most one native submission. A transport capable of independently proving exact readback completion and physical playout before user VAD may instead deliver `played(mark)` first, followed by the ordinary VAD/final affirmative. Never synthesize a `played`, or issue one on an estimated playback timeout.
- `ignored` does nothing. `stale` is not success. `accepted` reflects only the original native capability's matching result. The synchronous native end may have already closed this call while the result was in flight. A failed or ambiguous submission cannot be retried through this capability; finish the form on the desktop.
