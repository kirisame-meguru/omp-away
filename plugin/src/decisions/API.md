# Desktop decision integration

Import `DecisionCoordinator` from `./decisions`. The coordinator belongs to one host session generation and does not authenticate devices. The shared local broker is the only writer of `routing.json`; desktop runtimes subscribe to its snapshots and send field patches through `MobileRuntime.configure`. Never serialize a `PendingAsk`, a `DecisionCall`, or a submission capability.

Use one coordinator per desktop session behind request-scoped authorization. Share routing preferences and phone transport through the authenticated broker, never a coordinator or native submission capability. Snapshot eligible pinned identities at Ask birth and intersect that audience with currently authorized pins for every inbox, invitation and join. Require the same live pinned tunnel and joined request for media. Revocation closes the active call; a new enrollment never inherits old requests. Never forward an unfiltered shared inbox.

## Current native-live and touch runtime

The current coordinator returns `QuestionCall`: `question`, `signal`, `takeOver()`, `withdraw(reason)` and `close()`. Routing opens the host's `ctx.startLive` session after takeover and acknowledged `awayContext` delivery. Host API capability checks, not a release-number gate, determine voice availability. Native-live does not use the legacy scripted-readback size limits.

Authenticated phone `{type:"form",requestId}` receives `{type:"form",requestId,form,language?}` or `form:null`. The optional `language` tags the requested translation locale so the handset can discard/re-request an old-locale reply without losing drafts. `{type:"answer",requestId,values,notes?}` receives `{type:"answer",requestId,status,message}`, with status `accepted`, `invalid`, `stale`, `busy` or `uncertain`. Birth-audience authorization applies to both operations. Forms contain visible sections only; hidden values remain on the desktop. Raw notes contain exactly `{name,value,text}`; the desktop derives question and option labels and accepts notes only for selected enabled choices (or a valid Other answer).

Touch submission validates canonical native values before reserving one attempt. Active voice interactions reject touch submission as busy. Failed or ambiguous dispatch cannot be retried through the same capability. The broker retains request/connection-epoch/owner authority until the response, independently of inbox removal. Native acceptance requires matching native values and persisted option notes; companion acceptance requires that invocation's queued/recorded canonical receipt.

The legacy `createCall` proof gate and `VoiceSession` caller-turn binding remain separate integration APIs; current native-live routing does not call them. Their presence and isolated tests do not establish those safety behaviors in native-live. Native-live now uses `liveContext` once at pickup for bounded visible typed history, when it fits the media envelope; it does not run the legacy refresh loop.

Android owns the saved interface locale and sends optional `language:"en"|"ru"` on `list` and `join`. The last authenticated choice localizes desktop Away messages and is persisted separately from routing preferences. Each call snapshots its default at pickup; explicit conversational language requests still apply, while Settings changes affect subsequent calls. Question translations use a tools-disabled ephemeral turn, are cached per request/locale, and change presentation strings only. Failure preserves the original with a visible notice; native names, values, validation and submission authority are never model output. Update the app and desktop helper together; older handsets without language metadata retain their original protocol.

## Legacy scripted decision integration

- `offer(pending, ctx, project)` receives a live native or Async Ask capability. Native offers must have their guest controller bound. `false` means no mobile offer. Call `end(requestId)` synchronously whenever the source retires the capability, before resolving its result. Native finish, desktop answer, approval, room loss or abort retain their existing native retirement rules. `close()` seals the generation; do not reuse it after switching sessions.
- `configure({away,delayMs})` rings immediately in away mode; otherwise `null` disables escalation and a nonnegative delay is measured from creation. Each request rings once. Invalid persisted preferences must not enable ringing. A missed invitation or failed voice call does not expire the Ask.
- The runtime's async `configure(patch)` sends only changed preference fields to the broker. `/away` and `/away on` set `away: true` globally; `/away off` sets it false without clearing fallback. Status requests fetch a fresh snapshot. The broker persists before broadcasting, serializes concurrent patches, and supplies the latest state before a new runtime can offer requests. Reconfiguration does not end active calls or re-ring silenced/already-rung questions.
- `list()` returns inbox items; `silence(id)` affects notification only. `join(id)` requires an eligible request and no other active call. Bind that call to the authenticated tunnel/request and subscribe to `call.signal` before opening media. Hangup or disconnect calls `call.close()`, not `end()`. Reconnect obtains a fresh call with no old proposal.
- `await call.brief()` supplies bounded native question text immediately, without a model summary. Narrate `call.opening()` after join. The voice runtime answers contextual questions directly from silently supplied task snapshots and revokes confirmation with `call.interrupt()`. The explicit `call.consult(question)` API remains available to trusted integrations as a bounded tool-free side turn; it invalidates confirmation and cannot submit, but is not the voice runtime's answer path.
- Unsolicited provider delegations receive one bounded, terminal refusal on the SDK's default delegation-result channel, not a progress-only commentary update. The refusal starts no work, does not forward delegated content, and directs ordinary questions back to the realtime context. It cannot create a readback or submission.
- Provider audio streams as it arrives, paced on its 20 ms sample clock with a 100 ms handset lead. There is no assistant-final or handset-acknowledgment playback gate. Unchecked speech may be heard; it cannot alter the canonical proposal or independently authorize a submission. Transport backpressure remains bounded. A completed readback can only help repair stale tentative onset ownership when fresh microphone activity and aligned provider timing also support it.
- Send `call.speechStarted(id,startedAt)` when caller speech is recognized, retaining the first sustained local microphone-frame time when available. Send `call.speechFinished(id,text)` only for its uniquely associated completed user transcript. The voice adapter coalesces provider-final fragments under that onset until 1.5 seconds of stable recognition and live microphone silence; a provider final alone is not a completed caller utterance. Assistant speech and provider delegations cannot authorize a decision. Overlapping, duplicate or unbound turns cannot approve a proposal.
- A unique enabled option label in a single-select field drafts locally through the native validator. Other proposals and partial corrections use tool-free extraction. Native validation still rejects invalid values, disabled options, missing field evidence and inferred defaults. Hidden values remain local.
- A proposed reply carries `{kind:"say",text,draft}`. `draft` is an immutable list of visible labels and display answers; `text` instructs the voice model to briefly read them and ask whether to submit. Issuance alone does not enable confirmation. Check an already completed current response before requesting another; only missing or incorrect readbacks need `sendSpeakable(text,true)`. Field values are serialized as untrusted JSON, never executable instructions. Ordinary narration uses `sendSpeakable(text)`.
- Register a complete response with `call.readback(callerTurnId,responseId,transcript)`. The owner must match the current caller-derived draft. A tool-free verifier interprets all editable fields independently, with no expected-answer hints; native field/evidence validation and canonical value equality remain mandatory. The returned boolean does not submit. Response IDs are one-use and bounded; malformed, repeated or incomplete Submit prompts are rejected.
- After all corresponding audio is delivered, send the existing handset mark and pass only its authenticated, request-bound acknowledgment to `call.played(responseId)`. Acknowledgments alone have no authority. Call `outputStarted()` when new assistant speech revokes current, uncaptured eligibility; this must not rewrite evidence already captured at a caller onset.
- Only a separate explicit affirmative such as “yes”, “yes, submit”, or “go ahead” submits the unchanged proposal. Affirmative interpretation remains local. Capture only the current immutable draft and complete response already known at physical onset, with playback acknowledgment preceding it. Verification may finish for those captured observations, but later marks, transcripts or draft results cannot make an early onset eligible. Unknown, replayed and stale acknowledgments do nothing.
- Cancellation, corrections and consultation invalidate previous confirmation. Corrections require a new readback and explicit affirmative. A repeat reviews the current proposal again; it does not create a new Ask. A fresh call or request never inherits a draft. Duplicate finals cannot cancel already-owned verification or cause another submission.
- Pending classification does not erase the last validated draft. An interrupted or stale classification cannot overwrite it or a newer draft. Confirmation eligibility is still revoked immediately; a follow-up affirmative must obtain a fresh readback before another separate affirmative can submit. Failed or invalid completed extraction discards the proposal.
- `ignored` never indicates acceptance; the runtime clears visible proposal metadata rather than displaying a stale confirmation. `stale` is not success. Native `accepted` requires the original capability's matching result. Async `accepted` requires that invocation's canonical answer receipt with queued/recorded dispatch, not proof the model read it. Submission is attempted once; failure or ambiguity cannot be retried through that capability. Finish or review such a form on the desktop.
- Nontrivial proposals use extraction on the existing host model with the SDK's `minimizeEffort` control. Readback verification and explicit consultation retain session reasoning. Ordinary voice answers do not wait for either. The separate realtime snapshot marks missing/truncated visible context within its 24 KiB budget. Category-only timing contains no prompts, transcripts or answers.

Integration status: the legacy proof-gated path is not connected to current native-live routing. Do not claim end-to-end scripted voice confirmation from these APIs.

## Optional Async Ask source

`connectAsyncQuestions` in `runtime/async-ask.ts` discovers an in-process v1 source through `omp-async-ask:connect:v1` and `omp-async-ask:available:v1`. Discovery announces only version/session identity; the requesting trusted extension receives the live source through its callback. Neither plugin imports the other.

Async Ask owns canonical validation, persistence, delivery, source-generation disposal and one-shot offer retirement. Each immutable offer includes a canonical `id`, fresh opaque `requestId`, original `toolCallId`, title, HTML, blocked work, original `createdAt`, and `submitConfirmed(values,notes?)`. Optional `supportsOptionNotes:true` permits desktop-canonicalized option notes; older sources receive no notes. A source supplies complete snapshots and an abort signal. Treat snapshots as capabilities, not serializable protocol data.

The adapter uses the source's request ID and `async:${requestId}` deduplication key. Optional `PendingAsk.createdAt`, `deduplicationKey` and `context` preserve age and question metadata while native callers keep existing defaults. HTML and context remain untrusted data. An owner change revokes every old closure even when the session ID is unchanged; agent end does not revoke async offers.

Source submission returns `accepted` or `saved` with its own answer ID and delivery state, or `stale`, `invalid`, or `uncertain`. It removes attempted offers even when canonical validation/persistence leaves the question pending. Away preserves the returned receipt when a synchronous store notification has already retired the call. Saved/uncertain outcomes warn locally and leave recovery in `/questions`; never retry automatically or fabricate native tool results.
